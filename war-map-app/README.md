# War Map (iPhone app)

Your 2027 War Map as a real iPhone app. It runs the exact same War Map you use in Claude (all five tabs, every sheet), and adds:

- **Apple Health**: steps, weight, sleep and nutrition fill in by themselves. MyFitnessPal writes your food into Apple Health, so calories and macros arrive without screenshots. Steps always follow Health, so your steps habit ticks itself. Weight, sleep and nutrition only fill days you haven't typed in yourself.
- **Google Calendar**: Plan shows today's events. **Block time for today's priorities** puts your 3 priorities on your calendar in the first free gaps (8am–9pm), in order and at the length you picked. If you move a block in Google Calendar, it stays where you put it.
- **Your data on your phone**: everything is saved on the device, and photos are stored as files. Backup and restore work from Settings as before.
- **Claude features** (✨ feedback, reading a MyFitnessPal screenshot) work when you add an Anthropic API key.

Connect Apple Health and Google Calendar from **Settings → Connections** (the ☀︎ button, top right).

## Run it on your iPhone

Apple Health only works in an installed build, not in Expo Go. Everything else works in Expo Go if you just want a quick look (`npm run start:go`).

1. `npm install`, then `cp .env.example .env` and fill in the keys you want (both are optional).
2. Make a development build. You need an Apple Developer account for this:
   ```sh
   npm install -g eas-cli
   eas login
   npm run build:ios        # registers your iPhone, then builds in the cloud
   ```
   Install the build from the link EAS gives you. If you have a Mac with Xcode, `npm run ios -- --device` does the same thing locally.
3. `npm start` and open the War Map app on your phone. It connects to the dev server.

Rebuild (step 2) only when you change native settings or packages: `app.config.js`, `.env` Google client ID, or new dependencies. Day-to-day changes reload live.

## Google Calendar setup (once)

1. [Google Cloud Console](https://console.cloud.google.com/) → create a project → **APIs & Services → Library** → enable **Google Calendar API**.
2. **OAuth consent screen** → External, add yourself as a test user, and add the scope `.../auth/calendar.events`.
3. **Credentials → Create credentials → OAuth client ID → iOS**, bundle ID `com.balkisa.warmap`.
4. Put the client ID in `.env` as `EXPO_PUBLIC_GOOGLE_IOS_CLIENT_ID` and rebuild.

## Moving your data across

Your existing data lives in the Claude artifact. In the artifact: **Settings → Back up everything** and save the file to iCloud Drive or Files. In the app: **Settings → Restore from a backup** and pick that file. Photos aren't included in backups, so re-add any you want to keep.

## Updating the War Map

The app bundles the War Map page from the artifact. When you change the artifact in Claude, save its HTML and run:

```sh
npm run sync-map -- path/to/war-map.html
```

The Connections and calendar cards are added around the page, so they survive updates as long as the Settings sheet and Plan tab keep those names.

## How it fits together

| File | What it does |
| --- | --- |
| `App.js` | The full-screen War Map, plus the Health, Calendar, sharing and Claude handlers |
| `src/bridge.js` | Runs inside the page. Gives it the same `window.claude` runtime (storage, photos, downloads, AI) it has inside Claude, and draws the two new cards |
| `src/store.js` | Saves the War Map's documents (`days/…`, `habits/…`, …) to one JSON file, and photos to `_blob/` |
| `src/health.js` | Reads Apple Health and turns it into War Map day updates |
| `src/googleCalendar.js` | Google sign-in tokens, today's events, and placing priority blocks |
| `src/claude.js` | Claude calls for feedback and screenshot reading |
| `src/warMapHtml.js` | The War Map page itself (generated by `npm run sync-map`) |

Note on the Anthropic key: it's built into the app, so keep this build to yourself and set a monthly spend limit on the key in the Anthropic console.
